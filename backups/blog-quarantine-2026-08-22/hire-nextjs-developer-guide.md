To **hire a Next.js developer**, assess React fundamentals and the ability to make sound rendering, data, caching, performance, and deployment decisions. Framework API knowledge alone does not prove production readiness.

## Which skills should you evaluate?

Look for:

- Modern React and TypeScript.
- Next.js routing and layout patterns.
- Server and client component boundaries.
- Data fetching, mutations, caching, and invalidation.
- Authentication and authorization.
- Semantic HTML, accessibility, and responsive UI.
- Metadata, crawlability, and SEO migrations.
- Image, font, script, and bundle performance.
- Testing, error handling, and observability.
- Deployment and environment configuration.

Match questions to the Next.js version and architecture your project actually uses.

## What should the interview include?

Use a realistic task such as reviewing an interactive page, planning authenticated data access, debugging stale content, or improving a slow route. Ask the candidate to explain tradeoffs, failure cases, accessibility, and how the behavior will be tested.

## What portfolio evidence matters?

Inspect a live site and ask what the developer owned. Discuss traffic patterns, data sources, deployment, an incident, performance work, and the reason Next.js was selected. Lighthouse screenshots alone are not complete evidence.

## Frequently asked questions

### Is a React developer automatically a Next.js developer?

Not necessarily. React knowledge transfers, but production Next.js work adds routing, server rendering, caching, metadata, and deployment decisions.

### Should a Next.js developer know backend development?

They should understand secure data boundaries. The required backend depth depends on the product and team structure.

### Freelancer, employee, or agency?

Use an employee for long-term ownership, a freelancer for focused capacity, and an agency for cross-functional delivery.
