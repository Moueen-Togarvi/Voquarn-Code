Hire a **Next.js developer** when the project uses Next.js and requires informed decisions about routing, server rendering, caching, metadata, and deployment. Hire a **React developer** when the work is primarily component and client-application development outside a Next.js-specific architecture.

## What is the relationship?

React is the UI library. Next.js is a framework built around React that adds conventions and platform features for routing, server execution, rendering, optimization, and full-stack application delivery. Every strong Next.js developer needs React knowledge, but not every React role includes Next.js experience.

## When does Next.js experience matter most?

It matters for public websites with search requirements, hybrid server and client behavior, server-side data access, route-level caching, image and font optimization, and framework-specific deployment. Incorrect boundaries can create security, freshness, or performance problems.

## When is general React experience enough?

A React specialist may fit a client-rendered dashboard, component library, embedded interface, or existing frontend with separate platform ownership. If the team already has Next.js architecture and deployment leadership, the role may focus mainly on React UI delivery.

## How should candidates be evaluated?

Test React state and rendering knowledge, semantic UI, accessibility, TypeScript, data behavior, errors, and testing. For Next.js, add server-client boundaries, caching and invalidation, routing, metadata, secure mutations, and production diagnostics.

## Frequently asked questions

### Can a React developer learn Next.js quickly?

Often, but production judgment comes from applying its concepts to real systems. Adjust onboarding and review accordingly.

### Is Next.js only for SEO websites?

No. It supports marketing sites, ecommerce, applications, and full-stack products, although it is not required for every React project.

### Should one developer own frontend and backend?

Only when scope and experience support it. Clear responsibility is more important than the “full-stack” label.
