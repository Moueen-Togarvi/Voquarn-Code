To **hire a Python developer**, define the workload first: web backend, automation, data engineering, machine learning, or platform tooling. Python spans several disciplines, so generic “Python experience” is not enough evidence.

## What belongs in the role definition?

Describe the product, expected outcomes, existing stack, data sensitivity, deployment environment, collaboration model, and first ninety-day responsibilities. Separate essential experience from skills a strong engineer can learn.

## Which skills should be assessed?

Common foundations include:

- Clear, idiomatic Python.
- Data structures, typing, errors, and concurrency basics.
- Dependency and environment management.
- SQL and data modeling where relevant.
- Automated tests and debugging.
- Security and input validation.
- Version control and code review.
- Deployment, logs, and monitoring.
- Written reasoning and tradeoff communication.

Add framework, cloud, data, or ML depth according to the actual role.

## What makes a useful interview?

Use a realistic, bounded task: review code, design a workflow, investigate a slow operation, or add a small feature with tests. Ask the candidate to clarify requirements and discuss failure behavior. Avoid trivia and long unpaid projects.

## Employee, freelancer, or agency?

Hire an employee for sustained ownership, a freelancer for focused capacity, and an agency when delivery needs multiple roles or continuity. The best model depends on internal management capability and the duration of the need.

## Frequently asked questions

### Should a Python developer know Django?

Only if the project uses Django or similar web patterns. Data and automation roles may not need it.

### How important is GitHub activity?

It can be useful evidence but is not required. Professional work is often private.

### What is the strongest hiring signal?

Relevant problem-solving evidence combined with clear communication and responsible engineering judgment.
